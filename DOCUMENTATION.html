Project X — Technical Engineering Documentation Report

Candidate: M. Rajiv  |  Project: Project X (Photo Drive Logger)  |  Stack: React (Vite) + Node.js (Express) + Google Drive & Sheets API

1. Executive Summary & App Overview

Project X is a production-style, lightweight web application built to fulfill all requirements specified in AGENTS.md. It allows users to authenticate via Google OAuth 2.0, automatically creates and manages a dedicated Google Drive folder named after the user, uploads geotagged photos with multi-part streaming, extracts GPS EXIF data client-side, logs coordinates to an auto-created Google Sheet, presents a responsive gallery with authenticated thumbnails, plots coordinates on an interactive Leaflet map, and shares photos with Google accounts (specifically tested with su1@vr2.in).

4. Google API & Authentication Setup

  • OAuth 2.0 Code Flow: Frontend uses @react-oauth/google with postmessage redirect. The authorization code is sent to the backend, which exchanges it for access and refresh tokens.
  • OpenID Connect Profile Decoding: Extracts name, email, and picture directly from the cryptographically verified ID token without requiring the Google People API.
  • Drive Folder Auto-Creation: Searches for existing folder named M. Rajiv before creating. Never duplicates folders.
  • Google Sheets Logging: Auto-creates GPS Log spreadsheet and appends coordinates: Photo Name | Drive Link | Latitude | Longitude | Timestamp.

5. Security & Least-Privilege Design

  • Restricted Scope: Uses https://www.googleapis.com/auth/drive.file. The app can only see and edit files it creates. Personal user files in Drive are completely inaccessible.
  • Backend Secrets Isolation: GOOGLE_CLIENT_SECRET is kept strictly on the backend. No credentials leaked to frontend bundles.
  • No Public Links: Sharing uses Google Drive Permissions API (type: 'user', role: 'writer'). Files are never publicly exposed.
  • In-Memory Tokens: Tokens reside only in React runtime state and are never written to unencrypted storage (localStorage).

6. API Efficiency & Performance Optimizations

  • In-Session Folder & Sheet Caching: Uses in-memory Map caches (_folderCache and _sheetCache) to eliminate repeated Drive search API queries.
  • Parallel Fetching: Executes Drive photo list and Sheet metadata queries simultaneously via Promise.all.
  • Zero Memory Leaks: Object URLs generated for authenticated thumbnails are revoked upon component unmount via URL.revokeObjectURL().
